# Feature access

Feature grants and resource sharing are separate checks. `groups.capabilities` and the singleton `default_capabilities` row hold typed policies. A non-admin in any groups gets the union of those groups' grants; the configurable default applies only without memberships. An admin bypasses feature grants, not the ACL on another person's private resource. Within one policy, Create includes Use for agents, knowledge, skills and projects. Separately, each membership's per-kind sharing columns (`share_agents`, `share_knowledge`, `share_skills`, `share_projects`) control whether a non-admin may share that kind of resource into that particular group.

Revoking Create suspends resources authored by that person for _every_ reader, including the author and existing recipients, without deleting rows or grants. They reappear after regrant. A Use-only member may use accessible resources authored by others, but cannot manage their own suspended resources. Resource queries combine the recipient's Use, the author's Create and the ordinary ACL; the predicates live at the SQL read boundary, not just the client. Saved chat configurations never confer permissions on their user.

The server rechecks effective grants on each attempt (including retry, edit, structured answers, branch follow-up, queue promotion and steer), before resetting an answer. A generation holds its accepted configuration and offered tools for that attempt; a later revocation affects future attempts and live resource reads, not already persisted transcript content. The same policy gates direct service calls, conversational drafts, and background work. A selected forbidden feature fails rather than silently changing the requested job. The UI's capability snapshot only controls affordances and help content; it is not an authorization token. `resources.changed` invalidates it alongside resource lists.

Schedules retain their rows while permission is revoked. A due fire advances its cadence and records a `skipped` run without creating a chat; regrant enables future fires, not replay of skipped one-shots. Custom-tool authoring remains admin-only; basic text chat, account settings and historical transcripts have no feature grant.
